# Tinbox — iOS Game Boy Advance emulator

A native iOS (16+) GBA emulator by **Redfern's Outpost**, built from the design
handoff in `design_handoff_gba_player/`. SwiftUI for all UI, one UIKit view
controller hosting an `MTKView`, and the **mGBA** core (libmgba, C, interpreter
only — no JIT) behind an Objective-C++ bridge.

## Building without a Mac (GitHub Actions + Sideloadly)

`.github/workflows/build.yml` runs on GitHub's free macOS runners and does everything
Xcode would: builds libmgba, compiles the app, boots an iOS Simulator for screenshots,
and uploads an **unsigned `Tinbox-unsigned.ipa`**.

1. Create a GitHub repository (public = unlimited free macOS minutes; private = ~200 min/month)
   and push this folder (`Vendor/mgba` is git-ignored — CI clones it).
2. Open the **Actions** tab → *Build Tinbox* → download the artifacts:
   `Tinbox-unsigned-ipa`, `simulator-screenshots`, `build-logs`.
3. On Windows, install **Sideloadly** (sideloadly.io) and iTunes/Apple Devices drivers, plug in
   the iPhone, drag the `.ipa` in, sign in with any Apple ID → *Start*. Free Apple IDs re-sign
   every 7 days; paid developer accounts last a year. (Cloud saves need the iCloud capability
   and therefore a paid account.)
4. Optional: add a repository variable `TEST_ROM_URL` pointing at a ROM you own so the
   simulator screenshots show the emulator running, not just the library.

## Building on a Mac

Requires macOS with Xcode 15+, CMake ≥ 3.20 (`brew install cmake`).

```bash
# 1. Build libmgba for ios-arm64 and the simulator (arm64 + x86_64) → Vendor/mgba-dist
Scripts/build-mgba.sh
```

```bash
# 2. Open the project, pick a team under Signing, run on a simulator or device
open Tinbox.xcodeproj
```

`build-mgba.sh` documents the exact CMake invocation. Summary of what it does:

* `cmake -S Vendor/mgba -B Vendor/build/<slice> -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos|iphonesimulator -DCMAKE_OSX_ARCHITECTURES=… -DCMAKE_OSX_DEPLOYMENT_TARGET=16.0` with the GBA and GB/GBC cores (`M_CORE_GBA=ON`, `M_CORE_GB=ON`), `BUILD_STATIC=ON`, all frontends / debuggers / scripting / ffmpeg / lua / sqlite / libzip off.
* zlib comes from the iOS SDK (`libz.tbd`, linked by the app target); mGBA compiles its bundled **libpng** (PNG save states with embedded screenshots) and the bundled **minizip** (`.zip` ROMs).
* The three archives are merged with `libtool -static`, and `xcodebuild -create-xcframework` packages both slices together with `include/mgba`, `include/mgba-util` and the generated `include/mgba/flags.h`.
* `flags.h` must be the first mGBA header the bridge includes (it is): `struct mCore`'s layout depends on `ENABLE_VFS`, `ENABLE_DIRECTORIES`, `ENABLE_DEBUGGERS`, `MINIMAL_CORE`. The script also asserts that device and simulator were configured identically.
* `mgba-ios.patch` guards two lines in mGBA's `CMakeLists.txt`: the forced macOS `10.6` deployment target (applied to *any* Darwin build) and the forced `-flto` on Apple (which would tie the `.a` to one exact clang). Applied with `git apply`; the script refuses to continue if the patch stops applying so you notice.

To regenerate the Xcode project after adding files: `python3 Scripts/gen_xcodeproj.py` (or `xcodegen` with the provided `project.yml`).

## Engine integration (`Tinbox/Emulator/GBAEmulatorCore.mm`)

Written against the real headers, not from memory:

| Spec item | Implementation |
| --- | --- |
| Core creation | `GBACoreCreate()` + `core->init`, `mCoreInitConfig(core, "tinbox")`, `mCoreLoadForeignConfig` |
| Video buffer | `core->baseVideoSize` → 240×160, `core->setVideoBuffer(core, buffer, 240)`; native 32-bit `mColor` is R,G,B,X in memory → `MTLPixelFormat.rgba8Unorm` |
| ROM loading | `mCoreLoadFile` (resolves `.zip` through `mDirectorySetOpenPath`), then `mCoreAutoloadSave`, `core->reset` |
| Input | `core->setKeys(core, mask)` with `enum GBAKey` bit positions (`GBAKeyMask` in the header) |
| Timing | one `core->runFrame` per 60 Hz `CADisplayLink` tick on a dedicated thread; speed accumulator runs N frames for fast-forward and <1 frame/tick for slow motion, capped to a 14.5 ms budget |
| Save states | `mCoreSaveStateNamed` / `mCoreLoadStateNamed` through `VFileOpen`, flags `SAVESTATE_SCREENSHOT \| SAVEDATA \| RTC \| METADATA`; PNG thumbnail written from the framebuffer |
| Battery saves | `savegamePath` config → `mDirectorySetMapOptions` → `.sav` in `Documents/Saves`; `flushSaveData` syncs via `VFile->sync` |
| Cheats | `core->cheatDevice`, `createSet` / `mCheatAddLine` with `GBA_CHEAT_GAMESHARK`, `GBA_CHEAT_PRO_ACTION_REPLAY`, `GBA_CHEAT_CODEBREAKER`, `mCheatAddSet`, `mCheatRefresh` |
| Rewind | `mCoreRewindContext` (`mCoreRewindAppend` every 2 frames, `mCoreRewindRestore` for "Rewind 10 s") |
| BIOS | `GBAIsBIOS` validation, `useBios`/`bios` config picked up on reset, `core->loadBIOS` when imported mid-game |
| Patches | `core->loadPatch` (IPS/UPS/BPS applied in memory; the ROM file is untouched) |
| Sensors | `mPERIPH_ROTATION` (CoreMotion tilt/gyro), `mPERIPH_GBA_LUMINANCE` (brightness slider, `GBA_LUX_LEVELS`), `mPERIPH_RUMBLE` via `mRumbleIntegrator` → Core Haptics |
| Audio | `core->getAudioBuffer` drained after every frame into a ring buffer; `AVAudioSourceNode` at 32768 Hz stereo int16 |

## Using the app

* **Library** — tap a game for Play / Continue (newest save) / Load a save file / Make a patched copy / Delete. Long-press for a quick Play.
* **Import ROM** — opens the Files picker; by default the file is *moved* into the ROM folder (Settings › Library lets you switch to Copy, or choose any folder in Files/iCloud Drive as the library).
* **» button** (optional, Settings › Controls) — hold and slide right to fast-forward (up to the speed in Quick Menu), slide left to rewind live; release to return to normal. The Quick Menu toggle is the permanent fast-forward. The rotate button is optional too — the screen follows the phone's orientation by default.
* **Quick Menu** — Save (Auto slot), Load (newest state), Rewind 10 s, fast-forward speed, all save states (Auto + 9 slots, each with a screenshot), Time Capsule, cheats, settings, exit. Leaving a game always writes the Auto slot.
* **Time Capsule** — while you play, a snapshot (save state + frame) lands in `States/<game>/Timeline/` every few minutes (2/5/10 min, Settings › Advanced; also on exit, plus a Capture button). The Quick Menu's Time Capsule opens a day-grouped filmstrip of the whole playthrough; jumping to a moment first stashes the current spot in the Auto slot. Over ~240 snapshots the oldest 60% is thinned to every other one, so early history gets sparser instead of vanishing.
* **Settings** — Playback · Video · Controls · Appearance open by default; Library (ROM folder, import mode, box art, backup/restore), Connections (RetroAchievements; cloud saves later) and Advanced (volume, BIOS, sensors, About) start collapsed. In game, the first row opens the per-game overrides sheet.
* **Themes** — Modern, Tin (the app icon's olive drab & LED green), Outpost, Midnight, Grape, Forest, Ember, Sakura, Mint (Settings › Appearance), plus seven controller skins (Surplus pairs with Tin). The MENU pill carries the icon's power LED — green running, amber paused — the TINBOX eyebrow is stamped like the icon's badge, and booting a game plays a one-time clamshell lid-open.
* **Landscape** — Settings › Video › Landscape screen: Fit (true 3:2), Wide (10 % stretch), Fill.

## Files on device

`Documents/ROMs`, `Saves`, `States/<game>/slotN.ss` (+ `.png`), `Cheats`, `BIOS`, `Patches`, `Covers` (drop `<game id>.png` for box art), all visible in Files via `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`. Settings live in `UserDefaults`; per-game slots/cheats in `States/<game>/game.json`.

## Audio pipeline

The GBA's sample rate is not fixed: games set it through SOUNDBIAS (32768 / 65536 / 131072 / 262144 Hz — Pokémon's m4a driver uses 65536 Hz). The emulation thread reports the core's current rate after every frame; the audio thread pulls samples through a linear-interpolation resampler whose ratio is (core rate ÷ 48 kHz) corrected by ≤ ±1 % from the buffer fill level (dynamic rate control), with an 80 ms cushion. See `Tinbox/Emulator/AudioEngine.swift`.

## Scope notes

* **HQ2x** in the filter list is implemented as Scale2x/EPX in the fragment shader (a simpler smoothing filter); real HQ2x lookup tables are not ported.
* **RetroAchievements**: sign-in, game lookup by MD5 and the per-game achievement list (earned/locked) use the public `dorequest` API; Hardcore mode disables states, rewind and cheats. Runtime unlocking (memory watching) still needs rcheevos linked next to mGBA — `RetroAchievementsService` is the integration point.
* **Cloud saves**: iCloud uses the app's ubiquity container (enable iCloud Documents for the App ID; see `Tinbox.entitlements`). Google Drive has the provider hook but needs the GoogleSignIn SDK + client ID to be wired in.
* **Skin marketplace** and per-game profile management beyond the Layout Profiles sheet are spec-only, as in the handoff.
* This tree was authored on Windows and has not yet been compiled — the first GitHub Actions run is the compile check; fix anything it reports in `build-logs` and push again.
